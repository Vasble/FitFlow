# Завдання 2. Фази життєвого циклу та дорожня карта

## 2.1. Фази життєвого циклу

Оскільки проєкт веде розробку за Scrum, фази «Проєктування», «Розробка» й «Тестування» не виконуються одноразово послідовно, а повторюються щоспринту; нижче вказано, на яких спринтах кожна фаза переважає.

| **Фаза**     | **Зміст**                                                                                               | **Тривалість**                                      | **Артефакти**                                                                        | **Відповідальний**                               |
|--------------|---------------------------------------------------------------------------------------------------------|-----------------------------------------------------|--------------------------------------------------------------------------------------|--------------------------------------------------|
| Аналіз вимог | Уточнення вимог замовника (зокрема переліку абонементів), формалізація й актуалізація Backlog           | Спринт 0 (1 тиждень) + постійно по ходу проєкту     | SRS (Практичне № 2), Backlog вимог, матриця трасованості UC → FR                     | Мінчук Р. (Product Owner / full-stack розробник) |
| Проєктування | Архітектура клієнт-сервер, модель БД, UX кабінетів, специфікація інтеграції з SDK турнікета             | Спринти 1–2 (тижні 1–4)                             | ERD бази даних, API-специфікація (OpenAPI), Wireframes кабінетів, архітектурна схема | Full-stack розробник, Мобільний розробник        |
| Розробка     | Кодування функціоналу FR-01…FR-11 за пріоритетом MoSCoW                                                 | Щоспринту, Спринти 1–5 (тижні 1–10)                 | Вихідний код у репозиторії, юніт-тести, записи Code Review, звіт CI-збірки           | Full-stack розробник, Мобільний розробник        |
| Тестування   | Функціональне тестування нового приросту, регресійне тестування, перевірка критеріїв прийнятності (AC)  | Щоспринту + окремий приймальний спринт (тиждень 11) | Test Plan, Test Report, реєстр дефектів (Buglist), Acceptance Report                 | Тестувальник                                     |
| Розгортання  | Реліз MVP на проді, інтеграційне тестування турнікета на реальному обладнанні клубу, навчання персоналу | Спринт 6 (тиждень 12)                               | Release Notes, CI/CD pipeline, робочий build застосунку                              | Full-stack розробник                             |
| Супровід     | Підтримка після запуску, моніторинг інцидентів, виправлення дефектів, розвиток за фідбеком              | Постійно після тижня 12                             | Changelog, звіти про інциденти, план підтримки (SLA)                                 | Full-stack розробник, Тестувальник               |

## 2.2. Дорожня карта (Roadmap)

| **Спринт**       | **Тижні**   | **Фокус**                                                                    | **Ключові результати**                                |
|------------------|-------------|------------------------------------------------------------------------------|-------------------------------------------------------|
| Спринт 0         | Тиждень 0   | Уточнення вимог, картка проєкту, вибір SDLC-моделі                           | SRS затверджено, Backlog сформовано                   |
| Спринт 1         | Тижні 1–2   | Архітектура + реєстрація (FR-01), розклад (FR-02)                            | Working skeleton застосунку, ERD, API v0.1 на staging |
| Спринт 2         | Тижні 3–4   | Бронювання (FR-03), скасування (FR-04)                                       | Бронювання end-to-end працює на staging               |
| Спринт 3         | Тижні 5–6   | QR-код і інтеграція турнікета (FR-05), кабінет тренера (FR-08)               | Успішний тест на реальному турнікеті клубу            |
| Спринт 4         | Тижні 7–8   | Абонементи (FR-06), історія (FR-07), push-нагадування (FR-11)                | Push-нагадування працюють, кабінет клієнта повний     |
| Спринт 5         | Тижні 9–10  | Кабінет адміністратора (FR-09, FR-10), NFR (безпека, продуктивність)         | Адмінка готова, шифрування AES-256/TLS впроваджено    |
| Спринт 6 (Реліз) | Тижні 11–12 | Приймальне тестування, виправлення дефектів, розгортання, навчання персоналу | MVP запущено в проді, DoD релізу виконано             |

Перевірка узгодженості: дорожня карта організована спринтами, а не жорсткими послідовними фазами, що відповідає обраній моделі Scrum — кожен спринт дає перевіряємий приріст функціоналу, а не проміжний формальний документ, який має бути затверджений перед переходом далі, як це було б у Waterfall чи V-моделі.
