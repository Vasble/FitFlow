# ADR-0002: Серверна частина — єдиний REST API на ASP.NET Core, що розгортається в Docker

Статус: прийнято

## Контекст

Систему потрібно зробити за 12 тижнів командою з 3 осіб, де лише один розробник пише серверну частину (full-stack). Сервер має обслуговувати три різні клієнти: мобільний застосунок клієнта, веб-кабінет адміністратора й кабінет тренера. ТЗ вимагає Linux-сервер, контейнеризацію Docker і REST API, але не фіксує мову чи фреймворк. Додатковий час на вивчення нового стеку для такого терміну неприйнятний; з навчання вже відомий стек ASP.NET Core (він закладений у `.gitignore` проєкту).

## Рішення

Робимо один серверний застосунок — REST API на ASP.NET Core, спільний для мобільного застосунку й веб-кабінетів. Сервер запаковується в Docker-образ і запускається в контейнері на Linux (задачу контейнеризації T-13 уже виконано). Вибір бази даних і мобільного фреймворку (Flutter чи React Native) цим рішенням не охоплюється — вони фіксуватимуться окремими ADR.

## Наслідки

**Що дає:** команда працює на знайомому стеку й не витрачає тижні на вивчення нового; один API замість окремих бекендів для кожного клієнта; однакове середовище розробки й розгортання завдяки Docker.

**Чим доводиться поступитися:**

- Прив'язка серверу до екосистеми .NET: якщо до команди долучиться розробник без досвіду C#, йому знадобиться час на вхід.
- Мобільний застосунок (Flutter або React Native) не ділитиме код із сервером, тому моделі даних доведеться підтримувати узгодженими вручну (наприклад, через специфікацію API).
- Єдиний API означає єдину точку відмови: збій сервера зачіпає всі три кабінети одночасно (прохід через турнікет від цього не залежить — див. ADR-0001).
